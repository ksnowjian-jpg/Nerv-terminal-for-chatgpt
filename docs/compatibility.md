## 可读性修复记录

Work 流式生成再次触发撤回，失败记录显示前景本身为正常的 rgb(236,233,242)、背景为 rgb(21,20,28)，但祖先或 `_FadeIn_` 字段仍处于渐入，合成透明度约 0.160824 / 0.0688208，导致瞬时对比度约 1.54 / 1.17。该次故障与写作卡片或附件的静态配色不同，根因是把原生动画中间帧判成永久不可读。

修复将动画等待纳入可读性与启动流程：检测自身及祖先有限、运行中的 opacity 动画；原生 JS 流式渐入使用有上限的宽限；后台暂停时保持主题并在恢复前台后重查；瞬时透明度失败记为 pending，动画稳定后自动复查。0 透明度的动画起始帧同样等待，静态不可见装饰继续跳过。连续两次稳定失败才撤回。不会通过强制结束透明度动画或取消可读性保护来隐藏问题。当前 Work 会话重新应用后，主题 active、静态可读性通过；新增回归模拟真实记录的两种透明度、父子动画、连续文字分块、后台暂停、宽限超时、暂停／无限动画及动画后仍不可读的故障。

带来源标签的普通聊天另有真实配色遗漏：DIL 的中性软标签声明了内联 `background-color:var(--gray-75)`，即使回复区重新映射语义文字和背景变量，该标签仍为浅灰底。实机撤回前留下两条文字样本：前景 rgb(189,184,201)、背景 rgb(243,243,243)，对比度约 1.742。现补齐 secondary soft 背景族，并通过稳定的 `data-d-component="badge"`、secondary / soft / pill 属性，在受支持回复区成对映射这类标签的背景和文字；正常底色为 #242332，悬停为 #44404f，不改原始内联属性、不依赖编译类名、不替换图标或原生点击事件，独立文档继续排除。可读性保护仍检查真实标签文字，故障测试仍能撤回实际不可读的回复。

## 额度读取边界

当前版本已确认：额度直接位于官方头像菜单，无须进入设置。2026-10-27 实机点击新增面板“刷新可见额度”后，成功读到菜单的“使用情况 / 剩余 94%”，面板显示 94，aria-busy 恢复 false，官方菜单数量回到 0，主题保持 active。这是当时读取的账户值，并非固定额度或 API 流量余额。

用户点击刷新时，会识别唯一可见、带账户标签的官方头像按钮，模拟正常指针交互；只从该按钮关联的可见菜单读取带标签的单一剩余百分比，最多等待 2.5 秒。收起本次打开的菜单并恢复焦点；原已打开的菜单由官方交互决定，读取器本身不会主动关闭它。重复请求合并；页面卸载或关闭增强时取消未完成读取。菜单被遮挡、找不到头像或值不明确时显示原因，已有读数保留为缓存。

未读取时显示不可用；缓存明确标注最近读取时间，路由重绑后仍保留。后台每 5 秒只检查已经可见的菜单，绝不自行打开菜单。额度模块不采集聊天正文、拦截网络请求或调用内部接口，也不导航设置、账单或购买页面。重置时间仅在可见菜单明确提供时展示。
